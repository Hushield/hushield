# HuShield Rebrand & OSS Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the product identity from SpamFilter to HuShield (`com.brahy.hushield`) and add the
open-source scaffolding required before the repo can be published, leaving the project ready to push
to a public GitHub org.

**Architecture:** Two independent deliverables. Task 1–3 rename the Apple identity triplet (bundle
IDs, App Group, keychain access group) which is load-bearing at runtime and therefore test-covered.
Task 4–6 add licensing and contributor-facing documents, which are static files verified by presence
and link-correctness checks.

**Tech Stack:** Go 1.x, Swift 5 / iOS 17, XcodeGen (`ios/project.yml` is the source of truth — the
`.xcodeproj` is generated, never hand-edited), Make.

## Global Constraints

- Apple Team ID is `997DW79YCR` and does not change.
- New bundle ID root: `com.brahy.hushield`. Derived: `.kit`, `.CallDirectory`, `.MessageFilter`.
- New App Attest `APP_ID`: `997DW79YCR.com.brahy.hushield`.
- New App Group: `group.com.brahy.hushield`.
- License is Apache-2.0, plus a `TRADEMARK.md` reserving the HuShield name and App Store identity.
- `ios/SpamFilter.xcodeproj` is generated by `xcodegen generate`. Edit `ios/project.yml` only.
- Full gate is `make test` (Go with `-race -cover`, plus iOS via xcodebuild on a resolved simulator).
- Swift/Go **directory and type names stay `SpamFilter*`** in this plan. Renaming source symbols and
  directories is a much larger mechanical change with no functional benefit; only the *shipped Apple
  identifiers* and user-facing docs change here. This is a deliberate scope boundary.
